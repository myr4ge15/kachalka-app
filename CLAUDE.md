## Карта проекта (30 секунд)

PWA-журнал тренировок, React 19 + Vite 8, Dexie (IndexedDB, схема v7) как источник правды для
UI, Supabase как бэкенд, Vitest + RTL, Playwright для e2e. Версия — `package.json` (сейчас
5.11.x), она же видна внизу «Профиля».

- `src/lib/` — чистая логика (~60 модулей, у каждого свой `*.test.js`), без Dexie/React/сети.
- `src/db/` — доступ к Dexie + синхронизация (`repo.js`, `sync.js`, `sync/pull.js`, `sync/push.js`).
- `src/screens/` — 19 экранов; `src/components/` — презентационные куски, props-driven.
- `src/hooks/` — `useRevealFocus`, `useWorkoutFocus`, `useExportSelection`.
- `docs/` (git-ignored) — `ПАСПОРТ.md` (обзор + архитектурная история подсистем),
  `BACKLOG.md` (единственный источник задач + «Лог проходов»), `CHANGELOG-друзьям.md`,
  `plans/`, `reviews/`, `guides/`, `log/`.
- `supabase/` (git-ignored) — SQL, RPC, Edge Functions. Каноны функций — в `AGENTS.md`.

Первый шаг любой задачи: `AGENTS.md` → нужный раздел `docs/ПАСПОРТ.md` → `docs/BACKLOG.md`.

## Среда: чем я отличаюсь от Codex

- **Bash-инструмент в Cowork — это изолированная Linux-песочница, не PowerShell.** Пути там
  другие: рабочая папка видна как `/sessions/<session>/mnt/kachalka-app/`. Каждый вызов
  независим, `cd` не переносится — использовать абсолютные пути.
- **Файловые инструменты (Read/Write/Edit) работают по Windows-путям** (`D:\kachalka-app\...`)
  и предпочтительны для правок. Bash — для прогонов `npm`, `git status/diff/log`, `rg`.
- **Итоговый блок git-команд по DoD выдаём для Windows PowerShell** — его выполняет
  пользователь у себя, а не я в песочнице.
- Файлы в рабочей папке — CRLF, в git-блобах LF. `git diff` может показать файл целиком
  изменённым: это переносы строк, а не порча. Не «нормализовать» их попутно.
- Read-only git разрешён. `commit`/`push`/смена ветки/`.git/index.lock` — только по прямой
  просьбе.

## Проверки

```bash
npm test          # Vitest, основная проверка
npm run build     # Vite
npm run lint      # ESLint
npm run check     # lint + test + build (то же, что гоняет CI)
npm run test:e2e  # Playwright, только когда задача этого требует
```

Объём проверки — пропорционален изменению (см. DoD в `AGENTS.md`): код/тесты/поставляемая
конфигурация → `npm test` + `npm run build`; только документация или инструкции → достаточно
проверить diff, ссылки и непротиворечивость.

## Мои инструменты в этом проекте

- **Задачи и планы живут в `docs/BACKLOG.md`**, а не только во внутреннем todo-списке. Внутренний
  список — для прогресса в рамках сессии; результат задачи фиксируется в «Логе проходов».
- **Skills для документов** (`docx`/`pptx`/`xlsx`/`pdf`) в этом проекте почти всегда не нужны:
  вся документация — markdown в `docs/`. Использовать только если пользователь прямо просит
  файл в офисном формате.
- **Субагентов** (`Explore`, `Plan`) звать только по просьбе пользователя. Поиск по коду
  дешевле делать самому через Grep/Glob.
- **Не выдумывать содержимое git-ignored файлов.** В чистом клоне `docs/` и `supabase/` может
  не быть — тогда честно сказать об этом, а не реконструировать по памяти.
- Прототипы в `prototypes/*.html` — референс дизайна, не рабочий код.

## Красные линии (полный список — в `AGENTS.md`)

1. Экраны не обращаются к Dexie напрямую и не делают сетевых мутаций — только через `src/db/`
   и очереди в `sync.js`.
2. Схему Dexie (v7) и синхронизацию по умолчанию **не менять**.
3. Новая пользовательская сущность в `meta` — только вместе с синком (`SYNCED_KINDS` +
   белый список `upsert_user_meta`), иначе данные теряются при смене устройства.
4. Цвета — только через CSS-переменные в `src/index.css`, никакого хардкода в JSX/inline.
5. Серверные RPC не пересоздавать из старых `.sql` — у каждой функции есть канон.
6. Бамп версии в `package.json` по semver, если задача меняет отслеживаемый продукт.

UI и тексты — на русском. Мобайл-first, зоны тапа ≥44px, действия оптимистичные.
